# climate-auto-mode Planning Document

> **Summary**: **제어 단위는 구역(house_group)** 이다. 하우스 동마다 센서가 따로 있지 않으므로 센서·개폐기·유동팬·설정은 모두 구역 한 벌이다. 구역의 **"환경 자동 운전"**을 켜면 서버가 구역 센서(온도·습도·일사량)와 기상청 외부온도를 종합해 **구역 안의 개폐기를 모두 함께 % 위치로 단계 제어**하고 **유동팬을 순환·제습 목적으로 자동 운전**한다. 개폐기 **완전개방 시간(초)은 구역 설정 1개**다. **필수 장치가 모두 있고 값이 신선할 때만** 켤 수 있다. **40대 이상 사용자를 위해 화면은 단순하게**(새 메뉴 없이 구역 카드 안에서, 보이는 설정 3개). **1차는 개발서버에서만** 동작.

## 1. Overview

### 1.1 Purpose

현재 개폐기·유동팬 자동제어는 **사용자가 만든 개별 룰**(온도 히스테리시스 + 동작/대기 듀티사이클)로 동작한다. 룰은 "온도가 X 이상이면 열기" 같은 단일 조건이라 다음을 하지 못한다.

- 개폐기를 **조금만** 열기 (현재는 동작/대기 펄스 반복으로 결국 끝까지 열림 → 온도 출렁임)
- 시간대(일출·주간·일몰·야간)에 따라 **목표온도를 바꾸기**
- **외부가 추우면** 적게 열기, **습하면** 조금 열어 제습하기
- 맑은 날(일사 강함)과 흐린 날을 구분하기
- 유동팬을 **결로·고습·정체 공기** 기준으로 돌리기

**해결**: 구역 단위 **환경 자동 운전**(climate auto mode)를 추가한다. 자동 모드를 켜면 해당 구역의 개폐기·유동팬 룰은 자동으로 정지(보관)되고, 서버의 기후 제어기가 1분마다 종합 판단해 장치를 운전한다. 끄면 정지했던 룰이 원래대로 복귀한다. 그 전에 **시험 운전**로 판단만 기록하며 검증할 수 있다.

### 1.2 Background (현행 코드 기준)

- **룰 엔진**: `backend/src/modules/automation/automation-runner.service.ts` — 10초 크론, 룰별 히스테리시스(`deviation`) + 릴레이 사이클(`checkRelayCycle`) + 방향별 10분 캡. 개폐기는 opener_open/opener_close 페어, 방향(`hysteresisAction`)으로 대상 선택.
- **개폐기 위치 개념 없음**: 열림/닫힘 펄스만 있고 현재 몇 % 열렸는지 모른다. 게이트웨이(구역) 단위 `fallback_configs.opener_operation_seconds/opener_standby_seconds`(동작/대기)만 존재.
- **우선 동작 장치**: 비 감지 닫힘(`rain-override.service.ts`, `isOpenerRainOverridden(groupId)`), 고온 무대기 강제열림(`high-temp-override.service.ts`), 비상 정지 래치(`isGatewayLatched`), 개폐기 10분 초과 자동 OFF 백스톱(`devices.service.ts#autoOffStuckOpeners`).
- **환경 역할 매핑**: `env_roles` + `env_mappings`(구역별 role → 센서 or 기상청 필드). 현재 역할: internal_temp, internal_humidity, external_temp, external_humidity, co2, uv, rainfall, rain_detection. **일사량 역할 없음.**
- **룰 정지 사유 컬럼**: `automation_rules.disabled_reason`(045) — 'bulk' / 'manual' 선례. 같은 방식으로 'climate_auto' 사유를 쓴다.
- **온보드 센서 선례**: 무전압 우적센서(`raspberry-pi/fallback-engine/lib/rain-gpio.js`)가 `farm/{gw}/z2m/rain_sensor`로 z2m 형식 메시지를 발행 → 기존 센서 파이프라인이 그대로 저장. RS485 센서도 같은 방식으로 붙인다.
- **개발/운영 구분**: 개발서버 = 맥북(172.30.1.42, `npm run start:dev`, NODE_ENV=development, TypeORM synchronize ON). 운영 = 맥미니(Docker, NODE_ENV=production, synchronize OFF, 마이그레이션 수동).
- **구매 예정 센서**: 차광(+통풍팬) RS485 온습도계(Seeed SenseCAP S-THP-01A 등), RS485 일사량계(DFRobot SEN0640, 0~1800 W/m², Modbus-RTU, 기본 주소 1·4800bps, 레지스터 0x0000 = W/m²).

## 2. Scope

### 2.1 In Scope

- [ ] **개발서버 전용 차단(feature gate)** — 백엔드 환경변수 `CLIMATE_AUTO_ENABLED=true`일 때만 모든 기능 동작. 프론트는 capability API로 메뉴 노출 여부 결정. 운영 `docker-compose.yml`은 수정하지 않는다.
- [ ] **구역 단위 모드** — `off`(끄기) / `shadow`(화면 이름 "시험 운전": 판단만 기록, 장치 제어 안 함) / `auto`(자동 운전).
- [ ] **필수 장치 검사(준비 상태)** — 아래가 모두 충족될 때만 `shadow`/`auto` 전환 가능. 운전 중 하나라도 빠지면 즉시 **대기(일시정지)** + 알림, 복구되면 자동 재개.
  1. 실내 온도 (센서 매핑, 20분 이내 값)
  2. 실내 습도 (센서 매핑, 20분 이내 값)
  3. 일사량 (센서 매핑, 20분 이내 값) — **신규 역할 `solar_radiation`**
  4. 외부 온도 (기상청 매핑, 180분 이내 값)
  5. 우적센서 (rain_detection 매핑 + 장치 온라인)
  6. 개폐기 1쌍 이상 — 구역의 **모든** 쌍이 온라인 + **구역 완전개방 시간 입력됨**
  7. 유동팬 1대 이상 (온라인)
  8. 구역 게이트웨이 온라인 + 비상 정지 래치 아님
- [ ] **개폐기 완전개방 시간 입력(구역 설정)** — 구역마다 `완전 개방 시간(초)` 1개, 전문가 설정에 선택 `완전 닫힘 시간(초)`(미입력 시 개방과 동일). 구역 안의 개폐기는 모두 이 값으로 함께 움직인다.
- [ ] **개폐기 위치(%) 추정·단계 제어(구역 1벌)** — 모터 동작 시간 ÷ 완전개방 시간으로 구역 위치 추정, 구역의 모든 쌍에 같은 펄스. 위치를 모르면 가까운 끝으로 **원점 복귀** 후 제어.
- [ ] **쉬운 화면** — 새 메뉴·사이드바 변경 없이 '구역 관리'의 구역 카드 안 '환경 자동 운전' 띠에서 켜고 끈다. 설정 창에 보이는 설정은 낮 목표·밤 목표·완전개방 시간 3개뿐, 나머지는 '전문가 설정'에 접음. 큰 글자·큰 버튼·쉬운 말.
- [ ] **기후 판단 엔진** — 시간대별 목표온도(일출·일몰 기준 램프), 맑은 날 보정, 외부온도별 최대 개방 제한, 고습 제습 개방, 고온·저온 안전 동작, 유동팬(고습·결로·정체) 판단. **순수 함수**로 구현해 단위 테스트 가능하게.
- [ ] **기존 기능과 공존** — 자동(auto) 모드 진입 시 구역 내 개폐기·유동팬 대상 룰을 `disabled_reason='climate_auto'`로 정지, 자동 모드 해제 시 복귀(시험 운전는 룰 유지). 비 감지 닫힘·비상 정지는 항상 우선. 사용자가 수동·일괄 조작하면 해당 구역 자동 운전은 **사용자가 다시 고를 때까지 정지**(시간 제한 없음)되고, 기존 '자동제어 원복' 배너처럼 **[자동 운전 다시 켜기] / [자동 제어 룰로 돌아가기]** 중 하나를 선택해 복귀한다.
- [ ] **RS485 센서 수집(Pi)** — fallback-engine에 RS485(Modbus-RTU) 폴러 추가, 1분 주기로 읽어 z2m 형식으로 발행. Pi 로컬 설정 파일로만 켠다(기본 OFF).
- [ ] **판단 기록·가시화** — 매 판단(입력값·목표·결정·실행 여부) 기록(14일 보관), 구역 카드 배지, 상태/설정 모달, 최근 판단 로그, 실시간 소켓 갱신.

### 2.2 Out of Scope

- ❌ **풍속계·강풍 닫힘** — 이번 범위에서 제외(추후 별도 과제).
- ❌ **외부 온습도 실측 센서** — 외부 온도는 기상청 데이터만 사용.
- ❌ **Pi 폴백엔진 제어 로직 변경** — 서버 단절 시에는 기존 폴백 룰이 그대로 동작. (RS485 폴러 추가만 함)
- ❌ **기존 룰 엔진 로직 변경** — `automation-runner.service.ts`의 판단·실행 로직은 수정하지 않는다.
- ❌ **관수 자동화(일사비례 관수)** — 별도 과제. 이번에 수집하는 일사량 데이터는 이후 재사용.
- ❌ **운영서버 배포** — 개발서버 검증(시험 운전 1~2주 + 자동 모드 시험) 후 별도 결정.
- ❌ **CO₂ 제어, 차광막·보온커튼, 난방기 제어**.

## 3. Requirements

### 3.1 Functional Requirements

- **FR-01 기능 차단**: `CLIMATE_AUTO_ENABLED !== 'true'`이면 (a) 모든 climate-auto API는 404, (b) 크론·이벤트 리스너는 첫 줄에서 즉시 반환하고 DB 쿼리를 하지 않음, (c) `GET /api/climate-auto/capability` → `{ enabled: false }`, (d) 프론트는 관련 UI를 전혀 표시하지 않음.
- **FR-02 모드 전환**: `off ↔ shadow ↔ auto`. `shadow`/`auto`로의 전환은 준비 상태 검사(FR-03) 통과 시에만 허용, 실패 시 409 + 누락 목록. 전환은 활동 로그에 기록.
- **FR-03 준비 상태 검사**: §2.1의 8개 항목을 각각 `ok / missing / stale / offline` 상태와 해결 안내 문구로 반환. 신선도 기준: 센서 20분, 기상 180분(설정 상수, 환경변수로 조정 가능). 이 신선도 판단은 **climate-auto 모듈 내부에서만** 사용한다.
- **FR-04 운전 중 감시**: 매 판단 주기마다 FR-03을 재검사. 실패 시 상태 `SUSPENDED_MISSING` — 새 명령 발행 중지, 현재 위치 유지, 농장 푸시 알림 1회. 복구 시 자동 재개 + 알림.
- **FR-05 완전개방 시간(구역)**: 구역 설정 `opener_full_open_seconds`(10~540초 정수, 필수), 전문가 설정 `opener_full_close_seconds`(선택, 미입력=개방과 같음). 값이 바뀌면 구역 위치를 '모름'으로 초기화.
- **FR-06 위치 추정(구역 1벌)**: 구역의 모든 개폐기 쌍에 같은 시간만큼 동시 펄스, `Δ% = 동작초 ÷ 완전시간 × 100`으로 구역 위치 누적. 한 쌍이라도 명령 실패 시 전부 정지·위치 '모름'. 누적, 0~100 클램프. 다음 경우 위치 '모름': 최초, 완전시간 변경, 수동 조작, 비 감지 닫힘 동작, 게이트웨이 오프라인 복귀, 서버 재시작 중 이동 중단. '모름'이면 목표가 50% 이상이면 완전 열기, 미만이면 완전 닫기로 원점 복귀(완전시간 × 1.1).
- **FR-07 목표온도**: 주간 목표(기본 26℃), 야간 목표(기본 16℃). 일출~일출+120분 선형 상승, 일몰-120분~일몰 선형 하강(분 단위 설정). 일사량 ≥ 600 W/m²면 +1℃(설정). 일출·일몰은 구역 설정 좌표(기본 횡성 37.49, 127.98)로 계산.
- **FR-08 개폐기 판단 (구역 1벌, 우선순위 순)**:
  1. 비상 정지 래치 / 게이트웨이 오프라인 → 판단 중지
  2. 비 감지 닫힘 활성 → 개폐기 명령 안 함 (유동팬은 계속)
  3. 수동 정지 중 → 판단 중지(사용자가 복귀 방식을 고를 때까지)
  4. 저온 보호: 실내 ≤ 12℃ → 즉시 0% (대기시간 무시)
  5. 고온: 실내 ≥ 32℃ → 즉시 최대 개방(외부온도 제한 무시, 최대개방률 설정은 적용)
  6. 일반: 목표개방 = 비례게인(20%/℃) × (실내 − (목표 + 환기여유 1℃)), 고습(≥85%)이고 실내 ≥ 목표−1℃면 최소 10% 개방, 외부온도별 최대 개방 제한(≤5℃:10%, ≤10℃:30%, ≤15℃:60%), 1회 이동 최대 25%, 5% 미만 차이는 무시, 이동 후 4분 대기.
- **FR-09 유동팬 판단**: 켜기 = 습도 ≥ 85% 또는 (실내−이슬점) ≤ 2℃ 또는 실내 ≥ 32℃ 또는 (개폐 ≤ 20% 이고 일사 ≥ 200 W/m²). 끄기 = 습도 ≤ 80% 그리고 (실내−이슬점) ≥ 3℃ 그리고 실내 < 31℃ 그리고 정체 조건 아님. 그 사이는 유지. 최소 켜짐 10분 / 최소 꺼짐 5분. 켜짐 동안 구역 설정의 유동팬 동작/대기 주기 적용.
- **FR-10 룰 공존**: **auto 진입 시** 구역 내 개폐기·유동팬을 대상으로 하는 **활성** 룰을 `enabled=false, disabled_reason='climate_auto'`로 정지. auto에서 벗어날 때(off·shadow) 그 룰만 복귀. **시험 운전(shadow)은 룰을 정지하지 않는다**(기존 운전 유지, 판단만 기록). 자동제어 화면에 "자동 운전 중이라 멈춤" 표시. 정지된 상태에서 사용자가 룰을 켜려 하면 안내 후 거부(409).
- **FR-11 수동 조작 시 정지 + 복귀 선택** (일괄제어 원복과 같은 방식):
  - auto 운전 중인 구역의 개폐기·유동팬을 사용자가 수동 또는 일괄제어로 조작하려 하면, 프론트가 먼저 확인 팝업("자동 운전 중인 구역이에요. 직접 움직이면 자동 운전이 멈춰요")을 띄운다. 확인 시 해당 구역을 `STOPPED_MANUAL`로 전환한 뒤 조작을 진행한다.
  - 프론트를 거치지 않는 조작(음성비서·모바일 앱 등)도 서버가 사용자 명령을 감지해 같은 상태로 전환한다(안전망).
  - `STOPPED_MANUAL`은 **시간 제한 없이 유지**된다. 그동안 자동 운전·climate_auto로 정지된 룰 모두 동작하지 않는다(완전 수동).
  - 구역 관리 화면 상단에 **정지 배너**(기존 '자동제어 원복' 배너 바로 아래, 같은 모양)에 구역마다 한 줄씩 표시하고, 각 구역마다 둘 중 하나를 고른다:
    - **[자동 운전 다시 켜기]**: 준비 상태 재검사 후 RUNNING. 개폐기 위치 '모름' → 원점 복귀부터 시작. 준비 미충족이면 누락 목록 표시 후 거부.
    - **[자동 제어 룰로 돌아가기]**: 모드를 off로 바꾸고 `climate_auto`로 정지했던 룰을 다시 켠다.
  - 일괄제어(BulkControlModal)는 대상 장치가 속한 auto 구역 전부를 한 번에 정지하고, 멈출 구역 목록을 기존 '정지될 룰' 안내와 함께 보여준다. 구역 카드의 '환경 자동 운전' 띠에도 같은 두 버튼을 보여준다.
- **FR-12 RS485 수집**: Pi `fallback-engine`에 Modbus-RTU 폴러(기본 OFF, `/etc/smartfarm/rs485.json`로 활성화). 1분 주기 읽기 → `farm/{gw}/z2m/rs485_climate` `{temperature, humidity}`, `farm/{gw}/z2m/rs485_solar` `{solar_radiation}` 발행. 읽기 실패 시 발행하지 않음(값이 오래되어 준비 상태가 자연히 실패).
- **FR-13 RS485 장치 등록**: 환경 자동 운전 설정 창의 '필요한 장치'에서 "RS485 센서 등록" → 구역 게이트웨이에 센서 device(source='onboard', friendlyName='rs485_climate'/'rs485_solar') 생성(멱등). 환경 매핑은 기존 구역 환경 설정에서 사용자가 선택.
- **FR-14 기록·가시화**: 매 판단을 `climate_auto_logs`에 저장(입력·목표·결정·실행여부·사유), 14일 보관(일 1회 삭제). 소켓 `climate:status` 이벤트. 구역 카드 배지(자동 운전/시험 운전/확인 필요/수동 멈춤/비·대기).
- **FR-16 쉬운 화면**: (a) 새 메뉴 없음, 구역 카드 안 '환경 자동 운전' 띠(장치 섹션과 자동 제어 섹션 사이)에서 상태 한 줄 + 버튼 최대 2개, (b) 설정 창은 '필요한 장치 / 목표 온도 / 완전개방 시간 / 운전 방식' 4칸, (c) 화면 용어: 끄기·시험 운전·자동 운전, (d) 문구는 쉬운 말(설계 §5.5·§10), (e) 버튼 높이 48px 이상.
- **FR-15 권한**: 조회는 admin·farm_admin·farm_user, 변경은 admin·farm_admin. `X-Farm-Context` 적용(플랫폼 전용 라우트 아님). 구역 소유권 검사 필수.

### 3.2 Non-Functional Requirements

- **NFR-01 안전 우선**: 어떤 오류에서도 개폐기 열림·닫힘 동시 ON 금지(인터록 + 1초 간격). 한 번의 모터 동작은 최대 `완전시간 × 1.1`(≤ 594초)로 기존 10분 백스톱보다 짧게.
- **NFR-02 무영향**: 플래그 OFF 환경에서 기존 테스트 전부 통과, 기존 API 응답·스냅샷 변화 없음.
- **NFR-03 재시작 안전**: 서버 재시작 시 이동 중이던 모터는 `motor_stop_at` 기준으로 즉시 정지, 위치는 '모름' 처리.
- **NFR-04 성능**: 판단 주기 60초, 구역당 쿼리 10회 이내, 센서값 조회는 최근 시간 범위로 제한.
- **NFR-05 추적성**: 자동 모드가 발행한 모든 명령은 활동 로그에 `callerSource='climate-auto'`로 남긴다.

## 4. Success Criteria

- [ ] 운영 설정(플래그 없음)에서 기존 `npm test` 전부 통과, 신규 UI 미노출.
- [ ] 개발서버에서 필수 장치 하나라도 빠지면 모드 전환이 409로 거부되고, 누락 항목이 화면에 표시됨.
- [ ] 시험 운전에서 1~2주간 판단 로그가 쌓이고, 장치 명령은 0건.
- [ ] 자동 모드에서 개폐기가 단계(≤25%)로 움직이고 위치 추정이 실제와 ±15% 이내(육안 확인).
- [ ] 비 감지 시 자동 모드가 개폐기를 건드리지 않고, 비가 그친 뒤 원점 복귀 후 재개.
- [ ] 센서 값이 20분 넘게 끊기면 `대기` 상태 + 알림, 복구 시 자동 재개.
- [ ] 모드 OFF 시 정지했던 룰이 정확히 복귀(다른 사유로 꺼진 룰은 그대로).
- [ ] 자동 운전 중 수동 조작 → 확인 팝업 → 정지 배너 표시, 시간이 지나도 자동 재개되지 않고, 배너에서 '자동 운전 재개' 또는 '자동제어 룰로 전환'을 고르면 그대로 동작.

## 5. Risks & Mitigations

| 위험 | 영향 | 대응 |
|---|---|---|
| 위치 추정 누적 오차 | 실제보다 더/덜 열림 | 끝(0/100%) 도달 시 보정, 하루 1회 일출 전 원점 복귀(닫힘), 수동·우적 후 '모름' 처리 |
| 차광 불량 온습도계 | 한낮 과대 측정 → 과잉 개방 | 통풍팬 달린 차광함 권장, 시험 운전에서 기존 센서와 비교 |
| 기상청 외부온도 지연(1시간 주기) | 급변 시 개방 제한 부정확 | 최대 개방 제한에만 사용(주 판단은 실내값), 180분 넘으면 대기 |
| 룰 정지/복귀 꼬임 | 모드 OFF 후 룰 미복귀 | 사유 'climate_auto'인 룰만 복귀, 통합 테스트로 보장 |
| 서버 단절 | 자동 운전 중단 | Pi 폴백 룰이 이어받음(기존), 복귀 시 위치 '모름' → 원점 복귀 |
| 운영 오반영 | 의도치 않은 운영 동작 | 환경변수 차단 + 운영 compose 미수정 + 기능 브랜치 유지 |

## 6. Rollout

1. **Phase 0~6 개발** (설계 문서 §13 구현 지시) — 기능 브랜치 `feature/climate-auto-mode`.
2. **개발서버 적용**: `backend/.env`에 `CLIMATE_AUTO_ENABLED=true`, 마이그레이션 054 개발 DB에만 적용.
3. **센서 설치 후 시험 운전 1~2주**: 판단 로그 vs 실제 수동 운영 비교, 기본값 튜닝.
4. **자동 모드 시험**: 최대 개방률 50%로 제한 시작 → 문제 없으면 100%.
5. **운영 반영 여부 결정**: 별도 계획(이번 범위 아님).
