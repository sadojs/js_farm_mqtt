## 1. Overview

### 1.1 Purpose

`payroll_workers` 한 행이 근무조건(기간·시급·정산주기·기본시간)을 **한 벌만** 가져서:

1. 재입국 시 시작일을 바꾸면 이전 날짜가 모두 "근무 전"이 되어 **미확정 과거 정산이 0원**으로 재계산되고 달력이 비어 보인다.
2. 시급·공제를 바꾸면 **미확정 과거 기간이 새 값으로** 재계산된다.
3. 새 일꾼으로 재등록하면 로그인 계정이 둘로 갈리고 사람 단위 이력이 끊긴다.

### 1.2 해결

- 일꾼 = 사람(계정·연락처), **시즌 = 한 번의 고용**(기간·임금 조건·공제).
- 기존 계산 로직은 유지하고, 시즌 값을 덮어쓴 "유효 일꾼" 객체를 넘긴다.
- 기존 컬럼은 "현재 시즌 미러"로 남겨 구버전 앱·일꾼 본인 화면이 그대로 동작.
- 시즌 마감 시 그 시즌의 기록은 잠금(409 `SEASON_CLOSED`).

## 2. Scope

### 2.1 In Scope

- [ ] Phase 1 — 마이그레이션 055, 시즌 엔티티, 시즌 결정·마감·재고용 API, 기존 API 의 시즌 대응(하위호환)
- [ ] Phase 2 — 연간 결산 API `GET /worker-payroll/annual?year=`, 정산 이력 연도 필터
- [ ] Phase 3 — 화면: 연도 선택, 지난 시즌 일꾼 + 재고용, 시즌 헤더(칩·요약·마감), 연간 결산 탭(KPI·월별 차트·일꾼별 표·CSV)
- [ ] Phase 4 — 기타 고용비용(항공권·비자 등) 입력 + 결산 반영 (마이그레이션 056)
- [ ] Phase 5 — CLAUDE.md·설계 문서 변경 기록

### 2.2 Out of Scope

- 확정된 정산 snapshot 재계산·수정
- 기존 컬럼/테이블 삭제
- 새 npm 의존성(엑셀은 CSV 로 대체)
- 운영 배포(사용자 지시 후 별도)

## 3. 성공 기준

- 재고용 후에도 지난 시즌 달력·정산 금액이 **도입 전과 동일**
- 기존 API 응답 필드 변경 없음(추가만), 기존 테스트 전부 통과
- 연간 결산 합계 = 그 해 확정 정산 이력 합계

## 4. 위험

| 위험 | 대응 |
|------|------|
| 구버전 모바일 앱 번들이 시즌을 모름 | 미러 컬럼(D2) + `seasonId` 없으면 기본 시즌(D8) |
