## B. 비상 정지 (Emergency Stop)

**동작: 1회성(one-shot) — 정지 상태를 유지하지 않는다.**

1. 화면 버튼 → `POST /api/fallback-config/{gw}/emergency-stop` → MQTT `farm/{gw}/gpio/emergency-stop` (QoS1, retain 없음)
2. Pi `fallback-engine` 이 받으면 매핑된 관수·액비·팬·개폐기(열림/닫힘) 채널 전체에 OFF 1회 발행 (온보드 GPIO + Zigbee 모두). 이벤트 `safety_off` 기록
3. 정지 상태를 어디에도 저장하지 않음(서버 DB·Pi 파일 모두) → **해제 버튼도 없음**
4. 그 직후 다시 켜질 수 있는 경로: 서버 자동화 룰(다음 평가 주기, 10초~1분), 수동 제어, 관수 스케줄, 방재/타이머 만료, 서버 단절 시 Pi 폴백 엔진

문제점: ✅ 게이트웨이 소유권 검사 없음(다른 농장 관리자가 gatewayId 만 알면 실행 가능) / 실행자 기록이 'admin' 고정, 서버 동작 이력 없음 / Pi 실행 확인(ack) 없음 / Pi 가 꺼져 있을 때 보낸 명령은 유실 가능 / 개폐기가 중간 위치에서 멈춤.

권장: "정지 유지(래치)" — 서버에 정지 플래그(룰·수동·스케줄·방재 전 경로 차단) + Pi 에도 저장(재부팅 유지, 폴백 엔진 정지) + 명시적 "정지 해제" 버튼 + Pi ack + 동작 이력 기록.
