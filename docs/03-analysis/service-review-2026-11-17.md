# 서비스 정밀 검토 (2026-11-17)

동작 충돌 · 기능 개선 · 디자인 · 추가 아이디어. 코드 수정은 하지 않았다(분석만).

## 0. 결론

- **자동 제어에 실제로 재현되는 결함이 4건 있다.** 팬이 꺼지지 않거나, 히스테리시스가 무시되거나, 룰 두 개가 서로를 끄거나, 며칠 전 센서값으로 계속 제어한다. 운영에 실제 농가가 아직 붙지 않아 드러나지 않았을 뿐, 붙으면 바로 나온다. → 1순위.
- **운영 서버에 백업이 전혀 없다.** 일꾼 급여·정산 기록까지 맥미니 한 대의 디스크에만 있다. → 1순위.
- **MQTT 브로커는 계정 하나를 모든 Pi가 같이 쓰고 권한 구분이 없다.** Pi 한 대의 SD카드가 유출되면 모든 농장 장치를 제어할 수 있다.
- 디자인은 전반적으로 정돈돼 있으나 **깨진 화면 2곳**(페일오버 다크 모드, 농장 환경 점수 표시)과 색·용어 불일치가 있다.
- 가장 가치 있는 추가 기능은 **환경 경보(고온·저온)** 다. 지금 알림은 "센서가 고장났는가"만 보고, "하우스가 너무 덥다"는 알려 주지 않는다.

표기: **[재현]** 테스트로 실제 동작 확인 / **[확인]** 코드·운영 설정을 직접 읽어 확인 / **[추정]** 정황상 그렇게 보이나 실행으로 확인하지 않음.

## 2. 동작 충돌

### 2.1 재현된 결함 (자동 제어)

재현 조건: 팬 1대, 온습도 센서 1대, 운영에 저장된 것과 같은 형태의 룰. 결과는 실제 발행된 MQTT 명령 기준.

| # | 상황 | 기대 | 실제 | 위치 |
|---|---|---|---|---|
| R1 **[재현]** | 릴레이 주기 없는 히스테리시스 룰(습도 50±2). 운영에 이 형태 룰이 1개 있음 | 52 이상 켜짐, 48 이하 꺼짐 | 55 → 켜짐. 50(유지 구간) → **OFF 명령 없이 화면만 '꺼짐'**. 45 → **ON 명령을 다시 보냄**. 팬이 꺼지는 경로가 없다 | `automation-runner.service.ts` 254-263(유지 구간을 '조건 불충족'으로 처리), 918-922(`buildCommands` 가 방향을 안 봄) |
| R2 **[재현]** | 릴레이 주기 있는 히스테리시스 룰(습도 80±3) | 83 이상 켜짐, 77 이하 꺼짐, 그 사이는 유지 | 80(유지 구간)에서 **OFF 발행**. 사실상 83 한 점에서 켜졌다 꺼졌다 반복 | 같은 곳 + `clearRelayActivePhase` → `turnOffIfRuleOwned`. 10-05 의 "룰 종료 시 OFF" 수정이 유지 구간도 종료로 취급 |
| R3 **[재현]** | 같은 팬을 룰 2개가 제어(A 온도, B 습도). 둘 다 켜진 뒤 B 조건만 끝남 | A 가 유효하므로 계속 켜짐 | B 가 OFF 발행. A 는 "상태 변화 없음"으로 **다시 켜지 않음** | 룰별 `lastState` 만 있고 장치 단위 중재가 없음. 우선순위도 높은 룰이 먼저 실행돼 낮은 룰이 덮어씀(`order: priority DESC`) |
| R4 **[재현]** | 센서가 3일 전 값(습도 95)만 남기고 죽음 | 동작 안 함 + 경고 | 그 값으로 **ON 발행** | `getLatestSensorMap`, `getDeviceSensorValues`, `getEnvRoleMap`, 고온 우회 `getZoneTemperature` 모두 시간 제한 없음. Pi 폴백은 1200초 기준이 있는데 서버엔 없음 |

## 4. 기능 개선

1. **룰 화면이 실제 기준을 숨긴다.** "온도 ≥ 20°C"로 보이지만 편차 2가 걸려 있어 실제로는 22에서 켜지고 18에서 꺼진다. 센서 조건인데 배지는 "날씨"다(`rule_type` 이 모두 `weather`).
2. **끊긴 센서의 값이 현재 값처럼 보인다.** 구역 카드에 오프라인 센서가 "습도 59% 온도 22.6°C"를 시각 없이 표시. 이상 알림 화면에는 "10일 전" 값이 같은 크기로 나온다.
3. **대시보드 "가동 중인 장치 4/6"** 목록에 오프라인·대기 장치가 섞여 있다. 제목과 내용이 다르다.
4. **농장 환경 화면이 스스로 모순된다.** 같은 카드에 "양호 · 96점"과 빨간 "환기 긴급"이 함께 뜬다.
5. **개폐기가 지금 몇 % 열렸는지 모른다.** 열림/닫힘 펄스만 있다. 이미 `climate-auto-mode` 설계가 있으니 그 작업이 근본 해결.
6. **관수가 서버 재시작으로 끊기면 남은 구역을 버린다.** 진행 표시가 DB 에 있으므로 이어서 실행할 수 있다.
7. **알림 문구에 내부 이름이 그대로 나온다**("temperature 값 …", `rain_detection`). 판정 범위(-15~55°C 등)가 "횡성 방울토마토" 기준으로 코드에 박혀 있다.
8. **개폐기 수동 ON 에 시간 제한이 없다.** 릴레이가 최대 10분(백스톱)까지 통전된다. 구역에 "완전 개방 시간"이 있으니 그 값을 상한으로 쓰면 된다.
9. **Pi 가 재시작하면 릴레이 상태를 서버에 다시 알리지 않는다.** 서버는 켜짐으로 알고 실제는 꺼져 있다.

### 5.3 사용성

- **구역 관리 상단 버튼 4개가 4색**(주황·파랑·흰색·초록)이고, 모바일에서는 글자 없이 아이콘만 남는다. 카드 머리의 ⚙ ✎ ▼ 도 무엇인지 알기 어렵다. 대상 사용자가 40대 이상이면 글자가 있어야 한다.
- **개폐기가 "열림" 토글과 "닫힘" 토글 두 개**로 나온다. 둘 다 켤 수 없는 장치라 토글이 맞지 않는다. "열기 · 정지 · 닫기" 세 버튼이 실제 동작과 같다.
- **농장 환경 카드 라벨이 "온 / 습 / 외기 / 외습"**, 출처는 "HK_온습도 / te…"로 잘린다.
- **이상 알림의 첫 탭이 알림이 아니라 "활성 측정기" 목록**이다. 들어오면 알림이 먼저 보여야 한다. 측정기 아이콘은 전부 위성 안테나 이모지다.
- `Groups.vue` 2,978줄, `GatewayEnvSettings.vue` 2,161줄 — 화면 하나가 너무 커서 고칠 때마다 다른 곳이 깨질 위험이 크다.

## 6. 추가 아이디어

우선순위 순.

1. **환경 경보.** 구역마다 "온도 35°C 이상 / 5°C 이하, 습도 90% 이상이 N분 지속" 같은 기준을 두고 알린다. 확인하지 않으면 5분·15분 뒤 다시, 그래도 없으면 문자나 전화. 농가가 가장 먼저 찾을 기능인데 지금 없다.
2. **장치 목표 상태 중재기.** 지금은 룰·타이머·방재·비·고온·비상정지가 각자 장치에 명령을 보내고 서로 건너뛰기 표시로 조율한다. "장치마다 지금 원하는 상태 하나"를 우선순위 표로 정하고 한 곳에서만 명령을 보내면 R1~R3, C6 이 구조적으로 사라진다. `climate-auto-mode` 를 넣기 전에 하는 편이 낫다.
3. **명령 확인.** 명령 후 N초 안에 장치가 그 상태를 보고하지 않으면 재시도하고, 끝내 안 되면 "명령 미반영" 경보. C3·C4 해결.
4. **외부 감시 + 자동 백업.** 서버 밖(무료 가동 감시 서비스 등)에서 1분마다 확인해 문자. DB 는 매일 덤프해 다른 장비·클라우드로 복사하고 분기에 한 번 복구 연습.
5. **관수 건너뛰기 조건.** 토양 수분이 충분하거나 비가 오면 그 회차를 건너뛰고 이유를 기록.
6. **아침 요약 푸시.** "밤사이 최저 8.2°C, 관수 2회 완료, 알림 0건" 한 줄.
7. **룰 미리보기.** 저장 전에 "지난 24시간 데이터였다면 이 룰은 몇 시에 켜고 껐을지" 보여 준다. 히스테리시스·주기 설정 실수를 줄인다.
8. **설정 변경 이력과 되돌리기.** 룰·환경설정을 누가 언제 바꿨는지, 이전 값으로 복원.
9. **일꾼 급여명세서.** 정산 확정 시 4개 언어 PDF 를 만들어 일꾼 화면에서 내려받기.
10. **관리자 콘솔 농장 건강판.** 농장별 "오프라인 장치 수 · 미확인 알림 · 마지막 데이터 시각"을 한 표로.
